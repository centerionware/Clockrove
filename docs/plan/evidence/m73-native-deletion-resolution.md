_Status as of 2026-11-17. Source is based on main `ac82ec5`; the latest exact-head Actions gate is pending. Per owner instruction, no local build, test, formatter, or analyzer was run._

The preceding native change adds `changedCount`, `deletedCount`, initial dependent-reference conflict count, and initial session-overlap count to the native preview contract and Dart parser. Summary categories may overlap; deletion markers include historical tombstone revisions.

The next follow-up addresses six failures in exact-head Validate run `43905954272` on `1a316da`. Two comment/image graph tests left conflicts unresolved because deletion choice propagation was not scoped to the related comment and attachment records. The attached-image deletion test hit a foreign-key check because its raw Robolectric database did not enable the production database's foreign-key enforcement. The unique quote-value test expected a time-overlap count even though its only conflict was uniqueness. The preview-summary test lacked its Robolectric runner/API configuration. The unsupported-customer test expected a closed stage after a rejected apply; it has been replaced with a positive, safe causal-preservation test.

The follow-up uses distinct aggregate intents for preserving local content and preserving a local tombstone, scopes deletion choices to their entity graph, and includes explicit attached-image dependency choices. The test database now enables foreign keys. For a validated mutable revision-data row, preserving local content against a backup tombstone records a `BACKUP_MERGE` live head with the local-live and backup-tombstone revisions as parents. Preserving a local tombstone against backup live content records a `BACKUP_MERGE` tombstone with both revisions as parents and leaves the data row deleted. Preview and apply recognize the incoming revision as an ancestor of the resulting opposite-deletion merge, including the backup comment-deletion event, so replay does not recreate the conflict or import a contradictory event. Tests cover both causal directions, both parents, replay, unrelated card conflicts, restore/deletion of a comment with attached image, mismatched selections, preview counts, and foreign-key behavior. A separate immutable quote-decision case verifies unsupported `KEEP_LOCAL` remains rejected, apply stays blocked while unresolved, and the local row/head are untouched.

This is not full deletion-choice coverage. Generic preserve-local merges are safe only for mutable mapped rows whose revision payload, entity identity, and owning job match. A universal destructive/restore adapter is unsafe: deletion and restoration have table-specific foreign keys/cascades, media handling, session/timer constraints, and immutable-record triggers. Outside task comments and attachments, the opposite-side `APPLY_BACKUP_DELETION` / `RESTORE_BACKUP_CONTENT` adapters remain missing for `job`, `customer`, `site`, `column`, `card`, `session`, `template`, `automation`, `job_tax_rate`, `job_money`, `card_money`, `template_money`, `task_quantity`, `template_quantity`, `actual_cost`, `job_invoice_billing_policy`, `job_location_recording`, `quote_draft`, and `logo`. Keep M7.3 open and schedule focused table-family adapters after this PR validates.

Regression coverage includes the overlapping summary counts; comment deletion with an attached image; restoration of comment and image data; both local-preservation directions; replay ancestry; preserving an unrelated card edit; rejecting mismatched comment/attachment choices before writes; and checking both revision parents.

(1) `keepingLocalCommentDeletionDoesNotResolveUnrelatedCardEdit` re-created the comment/attachment deletion conflict on replay because preserving a local tombstone against newer backup live content returned without recording the reviewed resolution. `applyPreserveLocalDeletion` now always records the documented `BACKUP_MERGE` tombstone with the local tombstone and the backup live head as parents; the two no-op assertions in `BackupImportStoreTombstoneTest` that predated this contract now expect the merged tombstone and its single state-version bump while still asserting no data row returns. Apply now skips any staged row whose owning job has a permanent local deletion tombstone, resolving ownership through `job_id`, revision `job_id`, parent card, or parent session.
